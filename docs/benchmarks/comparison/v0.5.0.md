# Comparison with other unit libraries: Dimvexa 0.5.0

Hand-written summary of one full `benchmarks/run_all.sh` run (2026-11-12). Every number below is
copied from [`comparison.md`](comparison.md) (generated) and the raw files in
[`benchmarks/results/`](../../../benchmarks/results/). Method and rules:
[`../../benchmarking.md`](../../benchmarking.md). Earlier dated runs: [`history/`](history/).

## What was run

* Dimvexa built from commit `772e31c`, a clean checkout. Its library code (`crates/`, `bindings/`,
  Cargo files) is identical to the 0.5.0 release commit `4750b32`; only benchmark tooling and docs
  differ.
* One shared cloud VM: Intel Xeon 2.10 GHz, 4 cores, Linux 6.18, CPU governor not readable. rustc
  1.99.1, CPython 3.13.18, Node 22.23.4. Runners ran one after another.
* Competitor versions are exactly those in the lockfiles, verified by
  `benchmarks/tools/check_versions.py` before the run and again on the result files: pint 0.26.2,
  astropy 8.0.2, unyt 3.2.0, mathjs 13.2.0, js-quantities 1.8.0, convert-units 2.3.4, uom 0.36.0.
* Corpus `abf0a7cc771b2ed4`: 245 must-convert and 30 must-refuse cases. Two Dimvexa golden vectors
  with irrational expected values (`pi`, `180 pi^-1`, new in 0.5.0) are not cases, because the
  corpus holds exact rationals only; they are counted in the manifest.
* One run, not repeated. The machine is noisy: a difference is only called a difference where it is
  larger than the spread (MAD) of both sides.

case; its 1 ulp results are within the documented bound (`docs/precision.md`).

## Speed (prepared conversion, median ns per conversion, MAD in brackets)

Scalar means one prepared conversion applied to one value including the loop; batch is ns per element
for 1,000,000 values. Ceilings (a plain Rust or NumPy loop) do no unit handling and are in
`comparison.md`. Only the fastest competitor of each kind is shown; every library is in the
generated tables.

| Conversion | Dimvexa scalar | Best other scalar | Dimvexa batch 1M | Best other batch 1M |
|---|---|---|---|---|
| m/s to km/h | 0.693 (0.015) | uom 0.597 (0.124) | 0.571 (0.006) | unyt 0.589 (0.011) |
| psi to kPa | 0.848 (0.080) | uom 1.39 (0.014) | 0.680 (0.011) | astropy 0.593 (0.010) |
| degC to degF | 0.679 (0.008) | uom 0.721 (0.060) | 0.625 (0.013) | uom 0.738 (0.030) |
| kJ/(kg.K) to Btu/(lb.delta_degF) | 0.702 (0.030) | mathjs 12.8 (0.195) | 0.584 (0.010) | astropy 0.595 (0.011) |

How to read it:

* **Faster, larger than the spread:** psi to kPa scalar (Dimvexa 0.85 against uom 1.39); degC to degF
  batch (0.63 against uom 0.74); the compound scalar (0.70 against mathjs 12.8; uom cannot express
  it).
* **Not called a difference:** m/s to km/h scalar (uom 0.597 with a MAD of 0.124 against Dimvexa
  0.693); degC to degF scalar; m/s to km/h and compound batch (Dimvexa 0.01 to 0.02 ns below unyt
  and astropy, about one to two MADs).
* **Slower:** psi to kPa batch of 1,000,000: astropy (0.593) and unyt (0.636) are faster than Dimvexa
  (0.680), by more than the spread. Dimvexa's batch rows sit near the memory-bound ceiling (about
  0.6 ns), as do the NumPy-backed libraries, so batch speed is not a differentiator in this run.
* Dimvexa's exact path (rational arithmetic, no `f64` factor) costs 28 to 55 ns per scalar
  conversion and about 48 to 75 ns per element in a batch.
* One-shot (parse a string like `10 m/s`, build, convert): Dimvexa 1.2 to 1.9 us for the three simple
  conversions and 4.6 us for the compound one, against 4.5 to 9.5 us for the fastest competitor
  (mathjs in all four).

Python and JavaScript wall-clock figures on this VM are indicative only.

## What this does and does not support

* Supported by this run: on this corpus Dimvexa answered every must-convert case within 1 ulp, with
  no wrong value, and refused every ambiguous name; the other libraries did not on the same cases.
* Not supported: "fastest". Dimvexa's prepared conversions are at or near the best of the compared
  libraries, but not in every row (psi to kPa batch), and several rows are inside the noise.
* Not run: criterion and iai suites (`extras/`), any machine other than this VM, any repetition of
  the run, the Excel add-in.
* The corpus has 245 cases that were chosen by this project (40 from independent published sources).
  A different corpus can give different counts. The pint `ton` style defaults are reported as
  policy, not as errors.
